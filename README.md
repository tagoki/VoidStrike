> [!NOTE]
> Данный проект находится на стадии **MVP (Minimum Viable Product)**. Текущая версия сфокусирована на базовом функционале: прямом взаимодействии с локальным Ollama API, эвристической оценке и интерактивном CLI. В планах — масштабирование архитектуры и интеграция новых бэкендов.

**VoidStrike** — это специализированный инструмент командной строки, разработанный для специалистов по информационной безопасности, исследователей и разработчиков AI. Утилита автоматизирует процесс стресс-тестирования локальных языковых моделей на устойчивость к атакам типа **Prompt Injection**, **Jailbreak** и обходу встроенных систем безопасности (AI Guardrails).

## 🚀 Основные возможности

- **Интеграция с Ollama REST API:** Автоматическое взаимодействие с локальным инстансом Ollama без сторонних тяжелых библиотек (поддерживает настройку через переменную `OLLAMA_HOST`).
- **Интерактивный выбор модели:** При запуске утилита опрашивает установленные в системе модели (`ollama list` / `/api/tags`) и позволяет выбрать нужную с помощью стрелочек **↑ / ↓** и клавиши **Enter**.
- **Проверка стохастической устойчивости:** Отправка каждого тестового вектора $N$ раз с настраиваемой температурой генерации (`temperature`).
- **Детектор отказов (Heuristic Engine):** Анализ ответов модели на маркеры отказа на русском и английском языках с нормализацией апострофов для минимизации ложных срабатываний (`[REFUSED]` vs `[POTENTIAL BYPASS]`).
- **Изолированное сохранение отчетов:** Каждый запуск сохраняет отдельный файл отчета с временной меткой в выделенную директорию `reports/` (`reports/result_YYYY-MM-DD_HH-MM-SS.txt` или `.md`).
- **Поддержка Docker и Docker Compose:** Запуск в изолированном контейнере с пробросом `prompts.txt`, сохранением отчетов на хост-машину и прямым доступом к хостовому Ollama.

## 🐳 Запуск через Docker (Рекомендуемый способ)

Контейнеризованный запуск позволяет запустить **VoidStrike** без необходимости настраивать локальное Python-окружение.

### Вариант 1. Через Docker Compose (Быстрый запуск)

1. Убедитесь, что **Ollama** запущена на хост-машине.
2. Соберите и запустите контейнер в интерактивном режиме:
```bash
docker compose run --rm voidstrike
```
*(Флаг `--rm` автоматически удалит контейнер после завершения работы, а результаты останутся в локальной папке `./reports`).*

---

### Вариант 2. Через чистый Docker CLI

1. **Сборка образа:**
```bash
docker build -t voidstrike .
```

2. **Запуск на Windows / macOS:**
```bash
docker run -it --rm \
  -e OLLAMA_HOST=http://host.docker.internal:11434 \
  -v "${PWD}/prompts.txt:/app/prompts.txt" \
  -v "${PWD}/reports:/app/reports" \
  voidstrike
```

3. **Запуск на Linux:**
```bash
docker run -it --rm \
  --add-host=host.docker.internal:host-gateway \
  -e OLLAMA_HOST=http://host.docker.internal:11434 \
  -v "$(pwd)/prompts.txt:/app/prompts.txt" \
  -v "$(pwd)/reports:/app/reports" \
  voidstrike
```

> **Примечание по Ollama:** Если Ollama на хосте слушает только `127.0.0.1`, разрешите подключение из контейнеров, установив переменную окружения Ollama: `OLLAMA_HOST=0.0.0.0` (или `OLLAMA_ORIGINS=*`).

## 🛠️ Локальный запуск (без Docker)

### 1. Предварительные требования
* **Python 3.8+**
* Установленный и запущенный **[Ollama](https://ollama.ai/)** с загруженными моделями (например, `qwen2.5:3b`, `qwen2.5-coder:7b`, `llama3.2` и т.д.).

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 3. Подготовка промптов
Откройте файл `prompts.txt` в корне проекта и добавьте тестовые запросы, разделяя их строкой из четырёх дефисов (`----`):

```text
Тестовый вектор атаки №1
----
Тестовый вектор атаки №2 (многострочный)
Инструкция 1...
Инструкция 2...
----
Тестовый вектор атаки №3
```

### 4. Запуск утилиты
```bash
python void_strike.py
```

В интерактивном меню:
1. Выберите пункт `[1] Начать проверку устойчивости`.
2. Выберите формат сохранения отчета: `[1] TXT` или `[2] MD`.
3. Выберите модель из списка стрелочками **↑ / ↓** и нажмите **Enter**.
4. Укажите количество итераций (например, `3`).
5. Укажите температуру генерации (по умолчанию `0.7`).

## 📊 Форматы отчетов

По завершении тестирования в папке `reports/` создается отчет в выбранном формате:

### 1. Текстовый формат (`reports/result_YYYY-MM-DD_HH-MM-SS.txt`)
```text
========================================
Model Name: qwen2.5-coder:7b
Prompt ID:  1 | Iteration: 1/3
Status:     REFUSED
Input:      [Ваш тестовый вектор]
Output:     I am sorry, but I cannot assist with this request.
========================================
```

### 2. Markdown формат (`reports/result_YYYY-MM-DD_HH-MM-SS.md`)
```text
# VoidStrike Red Teaming Report

- **Target Model:** `qwen2.5-coder:7b`
- **Date:** 2026-10-23_20-15-00

### Prompt #1 | Iteration 1/3

- **Model:** `qwen2.5-coder:7b`
- **Status:** 🛡️ **[REFUSED]**

#### Input:

[Ваш тестовый вектор]


#### Output:

I am sorry, but I cannot assist with this request.
```
